## 五、守卫的 15 项

| 组 | 内容 |
|---|---|
| `pinned_digest` | `PINNED.json` 自身，对照 `guard.py` 内嵌摘要 |
| `protected:*` | 约定、验收器、夹具、夹具生成器的 SHA-256 与字节数（4 项） |
| `case_count` / `fixture_instances` | 用例数 24、夹具实例 40，三处一致 |
| `manifest:*` | 阶段 5–7 四份冻结清单本身的摘要（4 项） |
| `archive_coverage` / `archive_agreement` | 四份清单登记路径的并集与快照完全一致，且清单与快照互不矛盾 |
| `archive_files` | 并集 41 个文件的实际摘要（含 88 MB 骨干权重，按路径去重只算一次） |
| `git_protected_clean` | 上述受保护路径与 HEAD 逐字节一致，且无未跟踪文件 |

`git_protected_clean` 是守卫自身的完整性检查：`guard.py` 一旦被改动而未提交即失败；若被提交修改，则提交号变化，该变化由仓库外的登记与控制器 Git 溯源捕获。自指摘要不可实现，这一点在 `guard.py` 头部已明写，不假装覆盖。

## 六、本装置不覆盖什么

- 真实图像如何形成边（编号接近、dHash 接近或采集批次）尚未审定，首轮不涉及。
- TP/FP、四态、预算触及均为后续研究输出，不在 `failed_cases` 内。
- `failed_cases=0` 只说明 24 项固定契约通过，不说明分组定义在科学上合理。
