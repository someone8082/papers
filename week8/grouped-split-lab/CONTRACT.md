## 目标与仓库

目标为实现可复核的“图像分组与整组互补划分可行性检查器”。首轮开发仅回答两件事：给定图像键和无向边，产生稳定的连通分量；给定组大小，精确计算评价图像数为指定值的整组分配数。

仓库为 E:/ABB_Spray_Project/ideas/papers/week8/grouped-split-lab，具名分支为 main，无远端。论文总目录保留原结构。实验允许改动的唯一前缀为 src/。验收器、合成输入、守卫、此约定和数据清单均在该范围外，由启动前提交固定。

原始图像与阶段 3–7 的分数、协议和结果均在独立仓库外。首轮验收使用合成键、图和整数大小，尚不选择真实图像的边规则。真实分组定义仍按第八阶段提案审定。

## 输入输出契约

分组接口接收互异的完整字符串键及键对列表，返回全部连通分量。每组成员升序，各组按最小键排序，保证输入顺序不改变输出。边是无向的，重复边和自环不改变分组；重复节点键和未知边端点应显式拒绝。所有节点均须恰好出现一次，包括孤立节点。

计数接口接收正整数组大小列表和评价目标整数，返回任意精度非负整数。列表的每个位置代表一个身份不同的组，同大小组也必须分别计数。校准侧为评价组集合的补集，不切开任何组。空列表与目标 0 的计数为 1；负目标、目标大于总数、非正组大小应显式拒绝。非空有效输入若没有恰好凑成目标的组合，返回 0，表示真实不可行。

首轮只计算分组和分配数。图像侧如何形成边、如何抽取可行分配、如何计算 TP/FP 均属于后续任务，不纳入当前指标。

## 固定指标与验收命令

指标名 failed_cases，方向 lower，目标 0。固定 24 个顶层用例，每例通过为 0、失败为 1，总和为指标；内部包含多项断言的用例仍只计一次。

约定测量命令为从仓库根运行：

`E:/yingyong/an/envs/iad-week1/python.exe -B verify_metric.py`

该验收器待建立。它的最终非空 stdout 行为 JSON，例如 {"failed_cases": 3, "total_cases": 24}。指标解析键为 failed_cases。实现的断言失败、缺少接口或异常行为记为对应用例失败，成功完成测量时退出码为 0。验收器本身无法加载固定输入或出现基础设施故障时非零退出，以错误记录，不伪造指标。真实 baseline 在启动前测量并登记，本约定不预填基线。

## 保护检查

约定守卫命令为同一解释器运行 `-B guard.py`，通过退出 0，失败退出非零。守卫待建立，启动前必须通过基线核对。

保护内容包括固定验收器、固定合成输入与用例数 24、守卫自身以及此约定的摘要。另保存阶段 5–7 冻结清单及各清单所登记文件的摘要快照，守卫逐项核对，以发现独立仓库外的历史输入发生变化。守卫和验收器在执行时不改动 Git 可见文件，临时输出仅放入被忽略的 .scratch/。

控制器 scope 校验负责阻止 src/ 以外的 Git 改动。守卫提供额外的固定文件与外部归档核对。指标达到 0 只能说明固定验收契约通过，真实图像分组的科学合理性仍须单独审查。

采用前台模式，在当前对话中报告进展，初始化成功且状态为 active 后使用 Codex Goal 持续推进。每次试验只改 src/，由技能控制器 finish 完成提交、测量、保留或回退并追加历史。
